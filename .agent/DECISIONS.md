## D-011 Issue 立项的技术断言须实测验证（2026-10-18）

- 问题：#62 的背景断言"`hough_rho_resolution` 经 `std::max` 后 NaN 仍传播 → `static_cast<int>(NaN)` 是 UB"**经实测不成立**（`std::max(a,b)` = `(a<b)?b:a`，与 NaN 比较恒 false → 返回 `0.05`）。该断言来自 Planner 自己的扫描推理，历经 **5 轮"复核仍过门禁"却从未被编译验证**，且据此写出的验收标准第 4 条在改代码之前就已成立——是一条**不可能失败的标准**。若被 Executor 照单执行，会去给一个已经安全的表达式加守卫，并产出一份失实的发现报告。
- 决定：**凡以"某处存在 UB / 崩溃 / 缺陷"为核心卖点的 Issue，在放行进 `ready` 之前，Planner 必须用一次性程序实测该断言**（写在 `/tmp`，**不入仓库**、不改代码），并在 Issue 正文或评论中留下可复核的行号与实测输出。复核 ≠ 验证——"读一遍代码觉得对"不构成证据。
- 理由：Planner 的扫描产出是**推理**，而推理可以被证伪。本轮实测 4 条断言，**3 条与原文不符**（NaN/UB 定位错、可达性前提遗漏、崩溃严重性高估）。这类错误不会自己暴露，只会在 Executor 浪费一整个会话后才暴露，而当前循环已连续 6 天没有 Executor 活动，**没有反馈渠道去暴露它**。
- 影响范围：所有 Planner 立的新 Issue，尤其 P3 测试/质量类（其价值主张通常就是"这里有 UB"）；每日循环的第 3 步验收同样适用。实测成本极低（一个几十行的 `/tmp` 程序 + 一次编译），远低于一次错误立项的返工成本。
- 转正记录：不适用（本轮自定纪律，非用户决策）。

## D-008 KD-tree 最近邻替换暴力扫描时的平局语义（2026-10-10）

- 问题：ADR 下沉时若把 `pcl::KdTreeFLANN::nearestKSearch` 换成 O(n·m) 暴力扫描，"多个 secondary 点与 query 精确等距时选哪一个"两边是否一致？旧行为能否当作契约保留？
- 决定：**不保留旧行为作为契约。** 新实现用**严格 `<`** 扫描、保留最小下标，即"平局取下标最小者"，确定性且跨 PCL 版本/平台可复现。等价性论证只覆盖**非精确平局**输入；精确平局在 Issue 与执行报告中如实记录为"旧实现行为未文档化、新实现改为确定性"。
- 理由（Planner 2026-10-10 实证，临时程序未入仓库）：对 `pcl::KdTreeFLANN<pcl::PointXY>::nearestKSearch` 做差分——连续 double 坐标 10000 次抽样，最近邻下标/阈值判定/输出中点**均 0 处不一致**（bit 级等价）；整数网格坐标（制造大量精确平局）5000 次抽样，下标 412 处、中点 282 处不一致。说明 `KdTreeFLANN` 的平局选择取决于其内部树结构，**未文档化且可能随 PCL 版本变化**，不构成可依赖的契约。真实传感器坐标为连续值，精确平局概率为 0。
- 影响范围：#60（skidpad `ComputeCenterline`）及后续任何"KD-tree → 暴力扫描"类下沉；**差分测试的随机输入必须用连续值（浮点）而非整数网格**，否则会测到旧实现的未定义行为。#59（lidar_cluster PCA）不涉及最近邻，不受本条约束。
