# DIARY — 执行日报目录

> 建立者：Planning Agent（`plan-20261016` 轮，2026-10-16）。
> 建立原因：本目录此前**从未存在**（git 历史无记录），导致协作契约 1.8「日报是 Planner 次日验收的**唯一输入**」这条链路一直缺失，跨天验收只能靠 `HANDOFF.md` + `STATE.md` + git log + Issue 反推代行。反推能覆盖"零产出"的情况，但**覆盖不了有产出的日子**——所以必须补。

## 约定（与协作契约一致，此处只作就近提醒）

- **文件名**：`YYYY-MM-DD.md`，一天一个文件；同一天多个执行会话**追加**到同一文件，不新建第二个。
- **唯一写入者**：Execution Agent。Planner **只读不写**，也不代写内容。
- **必含小节**：做了什么 / 卡在哪（未解决）/ 验证情况（命令 + 真实退出码 + 关键输出摘录，未跑的项目写明原因）/ 明天第一步 / 需要用户决定 / 给 Planner 的信号。
- **不可变**：已写入的行永不编辑、永不重排。需要更正时用**新行追加**，格式：`更正：<原文> → <更正为>`。
  理由：历史一旦可被事后修改，次日验收读到的就可能是被美化过的证据，整个验收链失效。
- **漏写的后果**：等于打断跨天链路。Planner 会在下一轮如实写"昨日日报缺失，已用 X 反推"，并据此判断验收可信度。

## 与 HANDOFF.md 的分工

| 文件                | 性质         | 用途                                       |
| ------------------- | ------------ | ------------------------------------------ |
| `DIARY/<日期>.md`   | **追加式历史** | "那天做了什么"，供次日验收逐条核对         |
| `HANDOFF.md`        | **覆盖式快照** | "现在从哪继续"，每会话整体重写             |
| `STATE.md`          | 运行事实账本 | 进行中任务 / 分支 / 阻塞 / 最近提交        |

三者不可互相替代。
